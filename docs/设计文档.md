# NoJump 跳转拦截应用 —— 设计文档（Shizuku 冻结方案）

> 风格对齐 `/my_projects/ClipBridge`：Kotlin + Jetpack Compose + Material3、单 Activity 全代码 UI、SharedPreferences 持久化、`object` 单例、语义命名 + 中文注释。
> 方案选型：**UsageStats 轮询 + Shizuku 冻结目标应用**（参考开源 TriggerFreeze）。非无障碍、免 Root。

## 1. 项目概述

应用名 `NoJump`，包名 `com.example.nojump`。

核心能力：通过 **UsageStatsManager 轮询前台** + **Shizuku 免 root 系统权限**，在检测到"从源头应用跳转到目标应用"时，把**目标应用整体冻结**（`pm disable-user`），使广告根本拉不动它——**从源头阻止，而非事后补救**。离开源头应用后自动解冻，恢复正常使用。

第一里程碑目标：**来源→目标冻结闭环 + 三权限引导（Shizuku / 使用情况 / 前台服务）**。

## 2. 需求定义（本版范围）

| 编号 | 需求 | 说明 |
|---|---|---|
| R1 | 配置"来源应用"集合 | 在这些 App 内发生的跳转才触发冻结（如短剧组）|
| R2 | 配置"目标应用"集合 | 被冻结拦截的应用（如美团、起点读书）|
| R3 | 轮询检测到从来源跳到目标 → 冻结目标 | Shizuku `pm disable-user` |
| R4 | 离开来源 → 延迟解冻目标 | 延迟几秒，防快速切回绕过 |
| R5 | 本应用 / 系统 / 桌面永不冻结 | 白名单硬编码 |
| R6 | 防穿：冻结步骤轮询校验 | 消除状态偏移漏冻结 |
| R7 | 一键暂停/恢复入口 | 通知栏常驻通知带"暂停/继续"按钮，打游戏时暂停全部监控与冻结；恢复即续 |
| R8 | "去停 Shizuku"引导 | 对 Shizuku 工具进程本身有顾虑时，可一键跳转 Shizuku App 停服务 |

## 3. 为什么这个方案更优雅

### 3.1 能区分"手动打开"vs"广告跳转"
这是它相比无障碍 Back 方案的决定性优势：
- 广告跳转：**来源=短剧App**（触发集内）→ 冻结目标 ✓
- 手动点开：**来源=桌面/自己**（不在触发集）→ 不冻结 ✓

按"来源应用"配对，广告总是从短剧发起、手动总是从桌面发起，两者被区分开。

### 3.2 真正"阻止"，不是"补救"
冻结 = `pm disable-user`，目标应用被系统禁用，任何 startActivity 都拉不起来，无闪烁、无"再点一次确认"。

### 3.3 持久有效、无需常连电脑
授权一次 Shizuku，后台常驻；使用期纯前台服务轮询，与电脑无关。仅重启手机后需重新 adb 授权。

## 6. 核心逻辑

### 6.1 判定流程（RuleEngine 每轮）
```text
watchingRuleCheck():
    src  = watcher.readForegroundSource()     # 上一前台（在哪个App里发生跳转）
    cur  = watcher.currentForeground()        # 当前前台
    if cur 是 本应用/桌面/SystemUI: return
    if cur in 目标集 and src in 来源集:
        freeze(cur)                            # 冻结目标
    elif cur 不在 来源集 且 cur 之前被我冻结:
        延迟几秒后 unfreeze(cur)                # 离开源头，解冻

freeze(pkg):   Shizuku( "pm disable-user --user 0 pkg" )
unfreeze(pkg): Shizuku( "pm enable pkg" )
```

### 6.2 防穿 & 延迟解冻（借鉴 TriggerFreeze）
- 每轮都重新对目标校验证冻结状态，消除状态偏移（App 先显示 0.x 秒再被冻的漏网）。
- 离开源头后延迟 5s 解冻，防止"退出短剧又秒回"绕过。

### 6.3 权限清单
```xml
<uses-permission android:name="android.permission.PACKAGE_USAGE_STATS" />      <!-- 前台读取 -->
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE" /> <!-- API34+ -->
<uses-permission android:name="moe.shizuku.manager.permission.API_V23" />       <!-- Shizuku 客户端 -->
```

### 6.4 Shizuku 门槛（一次性")
- 手机装 Shizuku App → 连电脑 `adb`（或无线调试）授权一次 → 之后长期生效。
- 手机"设置 → 特殊应用访问 → 使用情况访问权限"给 NoJump 授权。
- 重启后需重新 adb 授权；国产 ROM 给 Shizuku 设后台保活。

## 7. 数据模型（object RuleStore）
```kotlin
object RuleStore {
    private lateinit var prefs: SharedPreferences
    fun init(ctx: Context) { prefs = ctx.getSharedPreferences("nojump", Context.MODE_PRIVATE) }
    val sourceSet: Set<String> get() = prefs.getStringSet("sources", emptySet())!!
    val targetSet: Set<String> get() = prefs.getStringSet("targets", emptySet())!!
    fun save(...)      // 持久化来源/目标集合
}
```

## 9. 风险与边界
| 风险 | 应对 |
|---|---|
| 重启后 Shizuku 失效 | 启动自检 + 引导再授权 |
| 国产 ROM 杀 Shizuku | 后台白名单引导 |
| 轮询非实时（0.x~1.5s） | 防穿每轮校验 + force-stop 兜底 |
| 误封用户主动用目标 | 来源触发规则区分（从桌面不冻）|
| 冻结影响目标正常使用 | 离开源头延迟解冻 |
